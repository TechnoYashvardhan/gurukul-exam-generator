Gurukul Exam Generator - Architecture & Workflow

Project Purpose

To provide teachers with a 100% private, eco-friendly, and highly intelligent exam generation pipeline without relying on external cloud APIs or complex technical setups.

Core Phases & Timeline

  • Phase 1 (Done): Next.js Frontend UI + Tailwind Cyber-Vedic Theme, Basic Pydantic Schemas.
  • Phase 2 (Done): FastAPI Backend integration with Agentic LLM Orchestration (Groq, Gemini, Ollama), JSON Auto-healing, and LocalStorage history.
  • Phase 3 (Pending): RAG Pipeline with FAISS Vector Database and SQLite for local document processing.
  • Phase 4 (Pending): Authentication & Advanced Export functionality.

System Architecture Diagram

The 4-Step Pipeline Workflow

1. Vidya (Template Creation)

The user defines the structure of the exam using the Template Builder UI. They specify the subject, grade, difficulty, Bloom's Taxonomy targeting, and section blocks (e.g., "10 MCQs for 1 mark each", "5 Long Answers for 5 marks each"). These templates are saved directly in the Browser Local Storage for instant retrieval.

2. Granth (Knowledge Base) [Phase 3 Target]

The user uploads a textbook PDF or provides a URL. The FastAPI backend processes it:

  1. Extracts text using PyMuPDF (with OCR fallbacks).
  2. Chunks the text into semantic blocks using Langchain.
  3. Computes vector embeddings using a local HuggingFace sentence-transformer model.
  4. Stores the text embeddings in a local FAISS Vector Store and tracks the document metadata in a simple SQLite database.

3. Rachna (Agentic Generation)

The user combines a Template and a Document. The backend's Agentic Orchestrator takes over:

  • It fetches the exact syllabus text relevant to the custom topic from FAISS.
  • It chunks the generation task asynchronously. Instead of overwhelming the LLM with a 100-question request, it maps over each section in the ExamTemplate and fires independent LLM generation calls per section in parallel.
  • The LLM Factory routes the request dynamically based on .env (Groq, Gemini, or Ollama).
  • It receives the JSON chunks, auto-heals any token truncation issues, and stitches the sections together into a perfect GeneratedExam payload.

4. Itihas (History)

The completed exam paper is handed back to the Next.js frontend, instantly rendered with the Cyber-Vedic print styling, and saved to the browser's local storage so it can be retrieved, edited, exported, or printed later without consuming more LLM tokens.
